# 当前场景 → 实体镜片建议

## 目标

分析当前画面，为用户提供偏振镜、近摄镜、黑柔镜、星光镜建议。不改变画面比例，不自动切换相机拍摄模式，不在预览上合成镜片效果。允许 NONE（不加镜片），也允许证据不足。

## 已实现的入口（0.4.0）

- 改为按需采集一组：5/10/15/20 张，间隔 100/200/500 ms，默认 10 张、200 ms；实际间隔还包含复制压缩时间。
- PixelCopy 只复制视频 Surface，不含 UI 黑边。原比例缩放，长边最多 1280，JPEG 90。
- 每次等新的渲染回调，不以旧图补齐；停流、超时、重复序号或部分采集失败则整批失败。相同静态场景的图像内容仍可能相同。
- 手机采样时间不是相机曝光时间，不能据此证明拍摄发生在触发之后；只能保证触发后等待新渲染并复制。
- 填电脑地址后通过 LAN HTTP 整组提交；留空只在内存备好，不上传。详见 TRIGGER_BATCH.md。
- 原单帧 SceneAnalyzer / SceneAnalysisPipeline 保留供后续复用，当前 UI 不运行连续模型调用。
- installedFilter 默认未知；模型尚未接入，不展示假的建议。

## 建议模型输出

JSON 字段：recommendation（NONE / POLARIZER / CLOSE_UP / BLACK_MIST / STAR）、reason、visibleEvidence（数组）、uncertainty、userAction。服务端应验证枚举及字段，不把模型文本直接用作相机控制命令。

后端提示词建议：

> 你是现场摄影镜片建议助手。根据提供的原比例预览图、用户拍摄意图、已安装镜片（未知时不得猜测）、可选主体距离，给出一项建议或 NONE。只陈述画面可见的证据。不要从单张图片推算准确的物理距离、偏振方向或镜片强度。不要将风格偏好当成客观必需。图像模糊/过暗/无法判断时，说明不确定性并给出可执行的补充观察动作。
>
> 偏振镜：关注玻璃、水面、湿润叶片等非金属表面的反射；不能保证消除所有反光，建议旋转镜片对比，金属反射或需要保留的反射不应盲目消除。
> 近摄镜：用于更近距离拍摄及小物细节；需确认主体距离和镜片的实际工作距离范围，不能仅凭主体占画面大就断言需要，也不能把运动模糊当成对焦距离问题。
> 黑柔镜：希望人像更柔和、亮部有晕光时可建议；已有雾化或强逆光造成细节损失时保守推荐，用户希望清晰记录时可选择 NONE。
> 星光镜：有清晰点光源且希望星芒风格时可建议；只有“夜景”不足以推荐，大片发光面或无点光源时不保证星芒。
> 输出符合约定字段的 JSON，reason 简短、visibleEvidence 有据可查，uncertainty 说明限制，userAction 给出安装/旋转/调整距离/维持现状建议。

镜片建议需要具体产品参数与实拍校验，模型的建议不能当成已验证的光学效果。可在后续使用连续两次一致的建议再更新 UI，减少提示跳变。

## 网络

复用 CameraSession.internetNetwork() 取得蜂窝 Network。后端请求显式绑定 socketFactory 及 DNS，或使用 Network.openConnection；不可直接使用默认网络（默认网络已绑定相机热点）。模型密钥放服务端，不放 APK。当前局域网传输使用已绑定的相机 Wi-Fi；公网接口才使用以上蜂窝路由。

## 本次卡顿排查及改动

已有日志证明 H.264 实时出流。旧版部分一秒窗口处理约 14–35 帧，有波动；累计“接收-显示”差值混有启动丢帧，不等同于当前队列长度或一秒延迟。

修改：解码输出每 8 ms 检查一次，不依赖新片段到来；对暂时无输入缓冲进行短时排空重试，不再 5 ms 就重建解码器；硬件支持时启用 Android 低延迟解码；解码后只显示最新可用输出，丢弃过时显示输出而不破坏压缩帧依赖；接收队列 64 片，等待超过 250 ms 则清空并请求关键帧恢复。

新增显示帧率来自 MediaCodec 实际渲染回调；queueMs 仅表示 SDK 回调后在本 App 的排队时间，不含相机、无线传输及 SDK 内部缓冲。修改没有降低相机拍摄分辨率、帧率或更改镜片/画面比例。新版本流畅度需要在红米更新后对比确认。
