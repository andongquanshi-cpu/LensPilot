# 运行位置与部署

Qoder 是开发工具，Codex 同样用于开发；运行时后端是本仓库 FastAPI 程序。视觉模型是可替换外部服务。ECS 是后端可选运行位置。调用模型 API 不需要另租服务器。

## 本地

相机/视频 → 本机后端 → 模型服务 → 决策 → ESP32 桥接/反馈。默认仅监听 127.0.0.1，前端构建由后端同源提供。普通摄像头和本地视频适配器只访问本机受控配置。

**必须单进程、单副本、一个设备**。帧、锁定、待完成指令、连接、意图均在内存中。不能使用多个 Uvicorn workers，也不能部署多副本负载均衡后宣称设备状态共享。SQLite 持久化日志/配置快照，不作为当前真实设备位置来源。

## Docker（提供配置，尚未在本机执行构建）

复制 .env.example 为 .env 后，执行 `docker compose up --build`。容器映射仍绑定 127.0.0.1:8000，使用非 root 用户和持久化数据卷。控制凭证显式填入 .env，或从数据卷 local-access.json 读取；不要将凭证嵌入镜像。镜像不包含 OpenCV/USB 驱动，画面通过电脑桥接上传。Docker 基础镜像和系统依赖的供应链锁定需部署时再按团队要求固定 digest。

## 可选 ECS

电脑画面桥接 → HTTPS 后端 → 模型 API → WSS 出站连接的电脑设备桥接 → ESP32。电脑桥接连接 ECS，ECS 不能访问电脑的 C:/ 路径、USB 或串口。

1. 部署前生成两个不同的至少 32 字节随机凭证，设置 OPTIC_CONTROL_TOKEN 和 OPTIC_DEVICE_TOKEN；控制台只使用控制凭证。
2. 更新 config.json.allowed_origins 为实际 HTTPS 控制台来源，不使用通配符。反向代理终止 TLS、转发 WebSocket Upgrade，并限制上传体积、请求频率和连接数。`/docs` 可仅内网开放。
3. 后端仍只运行一个实例，私网/loopback 上监听；只对外开放反向代理 443。不要公开 Vite 开发服务器或直接开放 8000。
4. 设置 OPTIC_TRANSPORT=bridge，电脑设备桥接使用 wss://域名/ws/device，画面桥接使用 https://域名。证书必须可信，不关闭 TLS 校验。
5. 电脑/服务器 NTP 对时，完成设备时效与去重约定；先只查询位置，再在装置可观察的情况下手动联调，最后开启自动。
6. 为 data 卷设置容量、备份和保留策略。现有日志有界；运行期帧和快照不落盘。应用健康检查 /api/health 只代表进程可响应，具体设备与模型可用性看已鉴权 /api/state。

仓库没有购买、发布或启动任何云资源，也没有实现互联网设备注册、租户隔离、多实例协调、HTTPS 自动签发或固件 OTA。设备凭证代表可信桥接；到位真实性最终取决于通信插件与实际传感能力。
