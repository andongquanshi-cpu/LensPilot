# 五步联动演示

打开本机 http://127.0.0.1:8000 。安卓仍向现有 8765 接收端上传，电脑必须连接手机热点。

1. 点击「开始下一轮」，再从安卓发送一批视频帧。
2. 页面接收、分析、给出建议。连接过镜片板时，沿用现有 Web Bluetooth 信号（CPL / CLOSE_UP / BLACK_MIST / STAR / KEEP），同一轮不重复发送。
3. 建议显示默认3秒后进入「等待拍摄」。开始前可在页脚调整为1/3/5/8/10秒。此计时仅推进展示，不表示硬件已到位。无蓝牙连接时仍可由现场同学人工辅助演示，页面会说明未确认发送。
4. 现场确认完成硬件动作后，按相机快门。安卓打开持续照片回传；接收端保存完整批次后，网页自动进入「成片展示」。
5. 成片保持显示，直到点击「开始下一轮」。界面内置「看一遍演示」不会控制硬件，也不会用占位图伪造第五步。

## 兼容现有安卓协议

真实照片的 manifest 必须包含 `source: CAMERA_PHOTO`、`contentKind: CAMERA_ORIGINAL_JPEG`、唯一 `requestId`、`cameraPath` 和 `frame-01.jpg`。现有上传样本已具备这些字段。不以“一张图”判断是照片，预览帧不会触发第五步。

通过相机文件名 `IMG_YYYYMMDD_HHMMSS_序号.jpg` 确认拍摄时间不早于本轮等待开始，且不是已收到的照片。请同步相机和电脑的日期、时间及时区；安卓的 `triggeredAtMs` 是单调时钟，不能当拍摄时间。没有可解析拍摄时间、旧照片、重复照片、其他轮次照片不会推进。若上传端以后支持 `roundId`，应填写本轮分析的 requestId。

本轮分析固定，不会被后续预览覆盖；成片不再送去模型选镜。新接口：本机 POST `/api/show/arm`（requestId、delaySeconds），POST `/api/show/reset`；GET `/api/show` 增加 `capture`、`complete` 状态，完成时返回 `photoRequestId`。图片仍通过 `/api/show/frame?request_id=...&index=1` 获取。

状态保存在单进程内存中。服务重启需重新开始一轮，不恢复等待拍摄。安卓新版源码不在此交接包内，本次沿用其已验证的文件落盘格式，未改 APK。
